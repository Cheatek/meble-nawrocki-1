Dodawanie zdjęć do galerii

Otwórz edytor · Zobacz galerię

Instrukcja dla właściciela

  1. Zaloguj się w edytorze kontem GitHub z prawem zapisu do repozytorium.
  2. Otwórz Galeria → Zdjęcia realizacji i dodaj pozycję do listy.
  3. Wybierz lub prześlij zdjęcie JPEG, PNG albo WebP. Powtórz dodawanie pozycji dla każdego kolejnego zdjęcia.
  4. Wpisz krótki opis widocznych mebli i wybierz kategorię. Przeciągnij pozycje, aby zmienić ich kolejność. Pierwsza pozycja pojawi się jako pierwsza w galerii.
  5. Zapisz wersję roboczą. W panelu przepływu pracy przekaż ją do sprawdzenia. Zaczekaj na poprawne sprawdzenie kompilacji i podgląd wdrożenia w GitHub/Netlify. Otwórz w podglądzie gallery.html i sprawdź zdjęcia na telefonie.
  6. Po sprawdzeniu wybierz publikację. Zmiana zostaje zapisana w gałęzi skonfigurowanej dla edytora, a hosting buduje nową stronę. Na stronie testowej nie oznacza to publikacji w witrynie produkcyjnej — właściciel musi osobno scalić gałąź.

Limit zdjęcia to 20 MB i 40 megapikseli. Animacje, SVG, HEIC i pliki innych typów nie są obsługiwane. Na telefonie wyeksportuj HEIC jako JPEG. Błędny plik zatrzyma nowe wdrożenie; ostatnia poprawna wersja pozostaje dostępna.

Prywatność: przed wysłaniem usuń lokalizację GPS i inne prywatne dane, unikaj twarzy, adresów i dokumentów klientów. Publiczna strona otrzymuje pomniejszone obrazy bez metadanych, ale oryginały pozostają w historii Git i mogą być publiczne, jeśli repozytorium jest publiczne.

Usunięcie pozycji z listy usuwa ją z galerii po publikacji. Nie usuwaj z biblioteki zdjęcia używanego przez inne pozycje. Usunięcie pliku nie usuwa go z historii Git.

Jednorazowa konfiguracja logowania przez GitHub

Te kroki wykonuje administrator strony tylko raz. Publiczną stronę wdraża Cloudflare Pages, natomiast projekt Netlify sensational-bombolone-3b6d44 obsługuje wyłącznie bezpieczne logowanie GitHub OAuth. Nie zmieniaj serwerów DNS. Potrzebujesz dostępu do tego projektu w Netlify oraz konta GitHub z prawem zapisu do repozytorium Cheatek/meble-nawrocki-1.

1. Sprawdź pomocniczy projekt OAuth w Netlify

  1. Wejdź na app.netlify.com i zaloguj się.
  2. Kliknij Projects, a następnie projekt sensational-bombolone-3b6d44. Jego adres to https://sensational-bombolone-3b6d44.netlify.app.
  3. Ten projekt służy jako broker OAuth. Publiczna domena meble-nawrocki.pl pozostaje w Cloudflare Pages.

2. Utwórz aplikację OAuth na GitHubie

  1. Otwórz ustawienia deweloperskie GitHuba. Możesz też kliknąć zdjęcie profilowe w prawym górnym rogu GitHuba, następnie Settings → Developer settings → OAuth Apps.
  2. Kliknij New OAuth App albo Register a new application.
  3. Wypełnij formularz dokładnie tak:
    • Application name: Meble Nawrocki CMS
    • Homepage URL: https://meble-nawrocki.pl
    • Application description: można pozostawić puste
    • Authorization callback URL: https://api.netlify.com/auth/done
  4. Kliknij Register application.
  5. Na stronie utworzonej aplikacji skopiuj Client ID. Następnie kliknij Generate a new client secret i od razu skopiuj sekret. GitHub nie pokaże go ponownie po opuszczeniu strony.

Uwaga: sekretu nie wpisuj do repozytorium, pliku config.yml, wiadomości e-mail ani komunikatora. Wkleisz go wyłącznie w chronionym formularzu Netlify w następnym kroku.

3. Podłącz aplikację GitHub w Netlify

  1. Wróć do projektu meble-nawrocki.pl w Netlify.
  2. Kliknij Project configuration → Access & security → OAuth.
  3. W sekcji Authentication Providers kliknij Install Provider.
  4. Wybierz GitHub, wklej skopiowane wcześniej wartości Client ID i Client Secret, a następnie kliknij przycisk zapisania lub instalacji dostawcy.

Ten projekt używa backendu github. Nie włączaj na potrzeby tej instrukcji Netlify Identity ani Git Gateway — dotyczą one innego wariantu konfiguracji Decap CMS.

4. Sprawdź identyfikator witryny OAuth

  1. Nie dodawaj zmiennych CMS_SITE_DOMAIN ani CMS_BRANCH w Netlify. Cloudflare ich nie odczytuje.
  2. Konfiguracja CMS zawiera już identyfikator sensational-bombolone-3b6d44.netlify.app i gałąź master.
  3. Po zmianie kodu wdrożenie produkcyjne sprawdzisz na GitHubie: otwórz repozytorium, kliknij najnowszy commit i znajdź zielony status Cloudflare Pages.

5. Sprawdź logowanie i publikację

  1. Otwórz meble-nawrocki.pl/admin/ w prywatnym oknie przeglądarki, aby nie użyć starej sesji lub konfiguracji z pamięci.
  2. Kliknij Login with GitHub albo Zaloguj przez GitHub.
  3. Jeśli GitHub pokaże ekran autoryzacji aplikacji Meble Nawrocki CMS, kliknij Authorize.
  4. Po powrocie do panelu kliknij Galeria → Zdjęcia realizacji. Dodaj jedno zdjęcie testowe, jego opis i kategorię, a następnie zapisz wersję roboczą.
  5. Sprawdź podgląd. Jeśli wszystko wygląda poprawnie, opublikuj zmianę. Cloudflare Pages powinien uruchomić nowe wdrożenie; jego status zobaczysz przy najnowszym commicie na GitHubie.

Najczęstsze problemy

  • Wracasz do ekranu logowania: sprawdź, czy callback w aplikacji GitHub ma dokładnie wartość https://api.netlify.com/auth/done.
  • Repository not found lub brak prawa zapisu: konto zalogowane w panelu CMS musi mieć dostęp do Cheatek/meble-nawrocki-1. W repozytorium na GitHubie otwórz Settings → Collaborators i nadaj temu kontu rolę pozwalającą zapisywać zmiany.
  • Zmiana nie pojawia się na stronie: na GitHubie otwórz najnowszy commit i sprawdź status Cloudflare Pages. Czerwony status oznacza błąd wdrożenia.
  • OAuth error lub site not found: sprawdź wartość site_domain w pliku admin/config.yml; musi to być dokładnie sensational-bombolone-3b6d44.netlify.app.

Dokumentacja źródłowa: Decap CMS — GitHub backend oraz Netlify — OAuth provider tokens.

Other hosting and local use

Run npm ci, npm test and npm run build from the repository root. Serve _site with a static HTTP server. Publish only _site, not the repository root: the build generates gallery HTML, thumbnails and sanitized display images. The public gallery needs neither JavaScript nor a running Node.js server.

For an archive or detached checkout, set CMS_BRANCH to the intended existing branch before building. The source admin/config.yml contains build-time placeholders and is not a deployable configuration.

The source gallery keeps the existing photos as a compatibility fallback. New CMS changes appear only in the generated site, so enable the build before using the editor; do not maintain the fallback list as a second content source.

On another static host, arrange an automatic build after content commits and either configure Netlify's OAuth broker for your site or supply a trusted HTTPS OAuth service by changing backend.base_url and backend.auth_endpoint in admin/config.yml. Never put a GitHub token or OAuth client secret in that file. GitHub Pages' default source-folder publishing does not run this Node build; it requires a separate workflow publishing the generated directory.

The editor loads a pinned Decap CMS release from jsDelivr; the public site does not. Network access to that CDN and GitHub/Netlify authentication is required for editing. When upgrading Decap, update its version and script integrity hash together.

Content and rollback

data/gallery.json is the gallery's source of truth. Each item has an image path, alternative text and category; list order is display order. Existing descriptions are generic and should be refined by someone familiar with the photographed projects. Adding a file to the media library alone does not add it to the gallery.

To undo a publication, revert the content commit in GitHub and let hosting rebuild. A hosting rollback can restore the previous deployment immediately, but also revert the content so the next build does not republish it. Check both gallery metadata and any image files when restoring a previous version.
